## 一、重构原则

1. **严格遵循 PRD**：所有 PRD 中的功能需求必须实现，不保留不符合 PRD 的代码
2. **渐进式重构**：分阶段实施，每个阶段可独立验证
3. **零丢失迁移**：数据模型重构需保证数据可迁移
4. **验证驱动**：每个任务完成后必须验证功能和跑测试

## 二、数据模型重构（Phase 0）

### 2.1 PRD 要求的数据模型

```
├── Experience（工作经历）
│   ├── id, company, position, startDate, endDate
│   ├── summary, content, tags
│   └── projects[]（关联项目）

├── Project（项目）
│   ├── id, title, slug, status
│   ├── repoUrl, demoUrl, techStack
│   ├── summary, content, coverImage
│   ├── highlights（亮点，加粗显示）
│   └── experience?（所属经历）

├── Travel（旅行）
│   ├── id, title, destination
│   ├── startDate, endDate, coverImage
│   ├── summary, content, tags
│   └── dayPlans[]（日程安排）

├── DayPlan（日行程）
│   ├── id, date, location
│   ├── content, images
│   ├── transportation, accommodation
│   └── travel（所属旅行）

├── LifeEvent（生活事件）
│   ├── id, title, date
│   ├── category, content, images
│   └── tags

├── LifeMonth（生活月 - 虚拟容器）
│   └── id, yearMonth（YYYY-MM 格式）
│   └── events[]（关联生活事件）

├── Knowledge（知识库）
│   ├── id, title, url
│   ├── category, tags
│   └── notes

└── Tag（标签）
    └── id, name, slug, category
```

### 2.2 当前问题

- 使用 Entry 统一多态模型，类型判断复杂
- 缺少 DayPlan 独立模型
- LifeEvent 与 Lifestyle 混淆
- 无独立 Tag 模型
- 无生活月虚拟容器

### 2.3 重构任务

- [ ] 创建新的 Prisma Schema，按 PRD 要求拆分为独立模型
- [ ] 编写数据迁移脚本，将现有 Entry 数据迁移到新模型
- [ ] 验证迁移数据的完整性和关联关系
- [ ] 更新 `src/generated/prisma/` 目录
